# Engineering Principles

## Measure the change

Optimization begins with a named signal: response time, memory use, crawl errors, asset weight, test coverage, or another reproducible measure. Vague improvement language is not a result.

## Release safely

Builds should be verifiable, releases should be observable, and rollback should be documented before production changes are made.

## Do not fabricate data

Technologies, metrics, outcomes, testimonials, and responsibilities belong in a case study only when they are supported by evidence.

## Preserve public contracts

Canonical URLs, metadata, structured data, API behavior, and indexed routes are compatibility contracts, especially during redesigns and catalog migrations.

## Start with accessibility

Semantic structure, keyboard operation, visible focus, motion preferences, and responsive readability are product requirements.

## Treat performance as architecture

Data shape, rendering strategy, asset preparation, cache boundaries, and request-path work matter more than late-stage cleanup.

## Observe production

Useful telemetry, smoke checks, health signals, and release notes turn production behavior into evidence.

## Respect privacy

Collect the minimum analytics needed to answer a product question. Consent, retention, and third-party behavior should be explicit.

## Name the maturity level

A prototype, deterministic preview, provider-ready boundary, deployed integration, and production service are different states and should be described differently.

## Validate AI-assisted work

AI can accelerate research, implementation, and review. It does not replace source verification, tests, security review, or professional judgment.
